# Windows 11 真机验收 · 麦克风自动校准

这是硬件验收清单，不是已经测出的真机结果。先使用两台扬声器，再补测含蓝牙的一组。

1. 在 Windows 录音设置中确认默认录音设备。优先使用独立麦克风，放在平时听音的位置。不要用正在测试的蓝牙耳机的麦克风，因为启用它可能切换蓝牙音频配置而改变延迟。
2. 开始声桥，确认两路同步都在播。先在同一位置对比未经校准的短促起音，再在声桥点击「麦克风自动校准」并确认。正常声音暂停，两路依次播放很短的低音量测试脉冲；麦克风只在此次校准期间打开。
3. 确认程序显示复测差和各输出的新延迟。通过阈值：两次独立测量之间每路变化不超 12 ms，补偿后最早与最晚两路在此麦克风位置的差不超 12 ms。回到正常播放后用脉冲或节奏明显的节目试听，最好用独立外部录音复核，不把程序自己测得的数值当作独立验收。
4. 保持播放 10 分钟，分别检查开始、5 分钟和 10 分钟的位置；确认没有持续走偏。该版原有 QPC 逻辑跟踪数字设备时钟，物理延迟的变化（例如蓝牙重新缓冲）仍可能需要重新校准。
5. 分别测试操作系统静音、禁用麦克风、降低设备音量、断开一台设备和开始校准后立即停止。应取消或报告失败，不采用低信号、高误差或不完整的测量，不覆盖手工配置，停止后不再打开麦克风。
6. 校准仅用于本次播放。用不同接收位置或重连设备后检查原手工设置仍在；需要重新校准时再按按钮。校准不生成、保存、上传录音文件。

## 可在无硬件环境运行的合成验证

`dotnet run --project validation/AcousticCalibration/AcousticCalibration.csproj`

覆盖两路/四路信号、48/44.1/16 kHz 麦克风采样、噪声与弱反射、第二轮实测补偿、静音、漂移式延迟跳变和缺失采集包。它不是 Bluetooth、扬声器或 Windows 驱动验收。

## 实现边界

- [Microsoft WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)：有些设备的回环复制发生在音频引擎，而不是实际发声点。声桥保留原先的数字时钟同步，新增声学测量覆盖两者之间不可观测的延迟。
- [Microsoft IAudioClock::GetPosition](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition)：设备位置可与 QPC 样本时间关联，供主机调度，不代替听音位置测量。
