# 声桥：并行输出原型验收

这不是已验证的发布版。仅使用已存在并经用户确认不直放声音的 Windows 音频输出。声桥不安装驱动，也不修改系统默认输出或 Windows 隐私设置。旧版「直放＋复制」与并行模式分开，不能把旧校准值自动迁移为并行模式的补偿。

## 设计
- 源音频进入指定无声设备。内置扬声器与外接音响都是独立渲染的目标，不存在原来一路不受控的直放。
- 共享带时间戳的 PCM 数据，按每个端点的 Windows 播放位置与其对应的 QPC 时间排程。这里共享的是时间基准，不是让不同硬件共享一块物理时钟。
- 缓存有上限、处理断点，信号缺失时补静音。不把软件看到的设备时钟当成声学测量，特别是不推断蓝牙或外置设备内部的时延。
- 原型不要求用户打开麦克风。实验室可用外部同一录音设备测实际出声；手动微调单路延迟只适用于已确认的相对偏差。

## 实机闸门（发布前）
1. Win11 上，已存在的无声输出应可接收测试媒体且本身听不到声音。分别用系统测试按钮确认两个真实输出都能单独出声；先测内置扬声器＋有线 USB 音频设备。如果用户实际用的是 3.5 mm 或蓝牙，另测该组合，不替代为有线结论。
2. 保持设备和麦克风位置固定。用同一个双通道采样设备（电气回录若安全可用，或声学测量）分别记录左右路径，不用各自独立录音时钟。比较旧版与新版的冷启动、持续 10 分钟、暂停后恢复、设备临时断开以及 Windows 默认输出更改。
3. 区分同一段音频的两路偏差、两路相对源总延迟，以及长时间的漂移。报告设备、连接方式、测量方法、偏差中位数和尾部值，不将合成数据的偏差当作听感。
4. 首次有线验收目标：相对偏差的绝对值 P95 小于 10 ms；10 分钟内不积累显著漂移、不间歇断音；无声输入确实没有额外的一路直放。单独记录总延迟，不把较慢设备的硬件延迟归因于播放器。
5. 若未取得实机结果，不标注“已修复”或“同步精度达标”，不上传替换先前交付版。

## 可复跑的软件测试
在源码目录运行 `dotnet run --project validation/timeline/Checks.csproj -c Release`。这覆盖有界 PCM 缓存、分数采样、缺帧补静音和时间映射，不替代真实端点验收。

## 初始原型限制
当前原型采用保守的共同排程提前量（85–210 毫秒，按源开始供包时的估计确定），不计设备自带的播放延迟和手动补偿；这不是可对外宣传的低延迟指标。它首先用于验证是否能消除两路互相追赶的主机侧时差。实测必须区分缓冲不足与硬件慢：收集首包到达、源包间距、各输出填充和缺帧，按观测到的尾部抖动缩减共同提前量；如果出现断音或端点时间戳不可靠，则保留原型标识。不要仅把数值从 85 改小就当成低延迟已经解决。

运行 `dotnet run --project validation/parallel-clock/Checks.csproj -c Release` 可验证同一 QPC 时间基准、时钟偏差模拟和输入中断恢复模拟。
